# Денежное дерево

Flutter-приложение для Android и iOS и сервер FastAPI. Три вкладки: рекомендации, дерево подписок и список ближайших платежей. Подписки можно вести без сервера: локальный режим доступен с первого запуска. Для аккаунта изменения сохраняются на устройстве и синхронизируются при доступности сервера.

## Быстрый запуск на Android

Запустите эмулятор, откройте `mobile/` и выполните `flutter pub get`, затем `flutter run`. На экране входа выберите «Продолжить без интернета».

Для тестового аккаунта запустите сервер с SQLite и `ALLOW_DEV_AUTH=true` по инструкции ниже. Откройте корень проекта в VS Code с расширением Flutter, выберите конфигурацию «Денежное дерево — разработка» и нажмите F5. На экране входа выберите «Войти без Яндекса».

## Презентация

Готовая презентация экспертной сессии из 13 слайдов хранится в [presentation/](presentation/Denezhnoe_derevo_expert_session.pptx).

В локальной папке `.deck-build/` лежат промежуточные PPTX (`authored.pptx`, `candidate.pptx`), тексты, таблицы и заметки в `content.json`, скрипты сборки и проверки, отчёты NDJSON и `validation.json`, монтаж шаблона и PNG каждого слайда шаблона (`source/`) и готовой версии (`final-preview/`). Скрипты используют локальный шаблон и абсолютные пути к инструментам. Папка исключена из Git.

## Что уже работает

- Ручное добавление, изменение, приостановка, отмена учёта и удаление подписок.
- Сортировка по ближайшему списанию, расчёт повторов с сохранением дня платежа, дерево с опадающими перед платежом листьями.
- Яндекс ID: OAuth authorization code + PKCE, сверка идентификатора и `client_id` на сервере, собственные короткие access-токены и сменяемые refresh-токены. Выход отзывает текущую сессию.
- Локальные уведомления на Android/iOS; пользователь выбирает дни и время. Приложение планирует ближайшие циклы после синхронизации.
- Проверяемый каталог цен и детерминированный расчёт экономии. Локальная открытая языковая модель через Ollama опциональна; без неё вопросы получают расчётный ответ.
- Экран подключения сервиса честно сообщает, что проверенных API для импорта пока нет. Вход через Яндекс ID не импортирует Яндекс Плюс.

## Запуск сервера

Нужен Python 3.11+ и PostgreSQL. Для локальной разработки можно использовать SQLite.

```powershell
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

В `.env` задайте случайный `JWT_SECRET` длиной не меньше 32 символов. Для PostgreSQL запустите БД из `compose.yaml` и оставьте `DATABASE_URL` из примера, заменив пароль. Для SQLite задайте `DATABASE_URL=sqlite:///./subscription_tree.db`. Запуск:

```powershell
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Для разработки без ключей Яндекса включите `ALLOW_DEV_AUTH=true`. Эндпоинт `/auth/dev` принимает вызовы только с loopback-интерфейса. В рабочем окружении оставьте `false`, используйте HTTPS и отдельный секрет JWT.

## Настройка Яндекс ID

1. Зарегистрируйте OAuth-приложение Яндекс ID для Android и iOS, выберите минимальные права `login:info` и `login:email`, зарегистрируйте redirect URI `subscriptiontree://oauth` (либо согласованный URI для обеих платформ).
2. Задайте `YANDEX_CLIENT_ID` и тот же `YANDEX_REDIRECT_URI` на сервере. `YANDEX_CLIENT_SECRET` нужен только если способ регистрации приложения его требует; мобильный PKCE-поток не должен хранить секрет в приложении.
3. Соберите мобильное приложение с тем же ID и URI. Android callback настроен в манифесте, iOS использует системный OAuth-сеанс.

Яндекс может требовать верификацию приложения перед публичным запуском. Без регистрации OAuth-клиента проверить настоящий вход невозможно.

## Запуск Flutter

```powershell
cd mobile
flutter pub get
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000 --dart-define=DEV_AUTH=true
```

`10.0.2.2` — адрес хоста для Android Emulator. Для iOS Simulator используйте `http://localhost:8000`. Для реального устройства укажите доступный HTTPS-адрес сервера. Реальный вход включается параметрами `--dart-define=YANDEX_CLIENT_ID=...` и `--dart-define=YANDEX_REDIRECT_URI=subscriptiontree://oauth`; `DEV_AUTH` опустите.

## Каталог и ИИ

Каталог намеренно пустой до внесения проверенных цен. Для загрузки подготовьте JSON-массив с полями `service_name`, `plan_name`, `category`, `amount`, `currency` (`RUB`), `period` (`weekly`, `monthly`, `quarterly`, `yearly`), `source_url` (официальная HTTPS-страница), `checked_at` (`YYYY-MM-DD`). Затем выполните:

```powershell
cd backend
python -m app.import_catalog ..\catalog.json
```

Цена старше 30 дней помечается как требующая проверки. Рекомендации сравнивают эквивалентные месячные расходы в одной категории. Для формулировки ответа открытой моделью запустите совместимый локальный Ollama и задайте `OLLAMA_URL` и `OLLAMA_MODEL` в `.env`. Без этих переменных сервер возвращает проверяемый шаблонный ответ. Дообучение модели — последующий этап после сбора обезличенного и проверенного набора вопросов и ответов; персональные расходы в обучение не включаются по умолчанию.

## Ограничения текущего среза

- Реальная авторизация Яндекса зависит от OAuth-регистрации и параметров проекта.
- Автоматического импорта чужих подписок нет без официального API и разрешений провайдера.
- Уведомления планируются для ближайших циклов и обновляются при открытии приложения; для бессрочного серверного push-планировщика нужен отдельный сервис.
- Начальная схема БД создаётся при запуске. Перед публичным развёртыванием следует добавить миграции и резервное копирование PostgreSQL.


## Офлайн-режим

- На экране входа выберите «Продолжить без интернета». Можно добавлять, изменять и удалять подписки, смотреть дерево и настраивать локальные уведомления без сервера.
- Данные сохраняются на устройстве между перезапусками через SharedPreferences (локальное JSON-хранилище, не SQLite). Очистка данных приложения или удаление приложения удаляет локальные данные.
- Локальные подписки отделены от аккаунта и не переносятся в него автоматически. После выхода из локального режима они сохраняются; повторно выберите вход без интернета.
- После первого входа в аккаунт приложение также открывается без сервера. Добавления, изменения, удаления и настройки напоминаний записываются в устойчивую очередь. Синхронизация выполняется при открытии приложения, возврате в него, обновлении экрана и каждые 30 секунд, пока приложение запущено. Фоновая синхронизация в закрытом приложении не реализована.
- Выход из аккаунта с неотправленными изменениями заблокирован, чтобы не потерять их. Недоступность обновления токена не очищает локальные данные. Для повторного входа есть пункт меню «Войти в аккаунт».
- Для повторной отправки создания без дублей сервер принимает необязательный UUID подписки. Обновите сервер вместе с приложением. При изменении одной подписки на разных устройствах применяются последние доставленные изменения; объединения отдельных полей нет.
- Каталог и рекомендации сохраняются после загрузки. После локальных изменений старые рекомендации очищаются до синхронизации. Новые ответы помощника и свежие тарифы требуют сервера; нейросеть на телефон не встроена.
- Проверки: `flutter test`, `flutter analyze`, для сервера из папки `backend`: `.venv/Scripts/python.exe -m pytest`.


## Физический Android без Яндекса (USB)

Для USB-подключения соберите APK с адресом `http://127.0.0.1:8000` и тестовым входом. Из корня проекта выполните:

```powershell
cd mobile
flutter build apk --debug --dart-define=DEV_AUTH=true --dart-define=API_BASE_URL=http://127.0.0.1:8000
Copy-Item build/app/outputs/flutter-apk/app-debug.apk ../subscription_tree-android-usb.apk
cd ..
```

1. Включите на телефоне режим разработчика и «Отладку по USB», подключите USB-кабель и подтвердите разрешение отладки на телефоне.
2. Из папки проекта запустите `powershell -ExecutionPolicy Bypass -File .\run-android-usb.ps1`. Скрипт выбирает физический телефон, при необходимости запускает сервер, настраивает USB-подключение, устанавливает APK без очистки данных и открывает приложение.
3. Нажмите «Войти без Яндекса». Используется один тестовый аккаунт `dev-local`. Это тестовая сборка для одного клиента.
4. Для онлайн-работы оставьте компьютер и сервер включёнными, USB — подключённым. После переподключения USB запустите скрипт ещё раз. Без подключения доступен локальный режим и ранее сохранённые данные аккаунта.

Скрипт перенаправляет порт через `adb reverse`. Сервер слушает только `127.0.0.1:8000` на компьютере.
