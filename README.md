# Денежное дерево

Flutter-приложение для Android и iOS и сервер FastAPI. Три вкладки: рекомендации, дерево подписок и список подписок. Для первого входа нужен доступ к серверу. После входа изменения сохраняются на устройстве и синхронизируются при доступности сервера.

## Быстрый запуск на Android

Запустите сервер с SQLite и `ALLOW_DEV_AUTH=true` по инструкции ниже. Затем запустите эмулятор и Flutter. В VS Code можно использовать конфигурацию «Денежное дерево — разработка».

Тестовый аккаунт разработчика:

- Телефон — `9870000001`, `+79870000001` или `89870000001`.
- Почта — `dev@moneytree.test`.
- Пароль — `MoneyTreeDev!2026`.

## Что уже работает

- Добавление вручную, из текстовых PDF-выписок Сбера и Т-Банка и через системное меню «Поделиться». Перед сохранением данные можно исправить.
- Поиск и фильтр по статусу подписок. Имена и иконки известных сервисов подставляются из каталога.
- Выписки анализируются на устройстве. Экран импорта показывает известные сервисы, повторяющиеся платежи и потенциально неактивные подписки. По банку запоминается последний день выписки. На сервер синхронизируются подтверждённые карточки подписок.
- Сортировка по ближайшему списанию, расчёт повторов с сохранением дня платежа, дерево с опадающими перед платежом листьями.
- Вход по телефону или почте с паролем. Сервер выдаёт короткие access-токены и сменяемые refresh-токены. Выход отзывает текущую сессию.
- Регистрация по российскому номеру телефона или электронной почте и паролю от 12 символов.
- Локальные уведомления на Android/iOS; пользователь выбирает дни и время. Приложение планирует ближайшие циклы после синхронизации.
- Проверяемый каталог цен и детерминированный расчёт экономии. Локальная открытая языковая модель через Ollama опциональна; без неё вопросы получают расчётный ответ.
- Экран подключения сервиса честно сообщает, что проверенных API для импорта пока нет. Вход через Яндекс ID не импортирует Яндекс Плюс.

## Запуск сервера

Нужен Python 3.11+. База выбирается через `DATABASE_URL`. Для локальной разработки подходит SQLite. PostgreSQL можно запустить отдельно через Docker Compose.

```powershell
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

В `.env` задайте случайный `JWT_SECRET` длиной не меньше 32 символов. Для PostgreSQL запустите БД из `compose.yaml` и оставьте `DATABASE_URL` из примера, заменив пароль. Для SQLite задайте `DATABASE_URL=sqlite:///./subscription_tree.db`. Запуск:

```powershell
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Uvicorn запускает HTTP-сервер FastAPI. При загрузке приложения SQLAlchemy открывает базу из `DATABASE_URL` и создаёт отсутствующие таблицы. SQLite хранит данные в `backend/subscription_tree.db`, если запустить сервер из `backend/` с настройкой выше.

С `ALLOW_DEV_AUTH=true` сервер добавляет данные для входа к аккаунту `dev-local` при запуске. Тестовый аккаунт принимает пароль через `POST /auth/login` при соединении с loopback-интерфейса. При выключенном флаге сервер отклоняет этот логин. В рабочем окружении используйте `ALLOW_DEV_AUTH=false`, HTTPS и отдельный секрет JWT.

## Регистрация и удаление аккаунта

Введите телефон или почту и пароль. Контакт используется как логин. Регистрация сразу открывает приложение и не требует настройки отправки писем или SMS.

В верхнем меню «⋮» доступны «Выйти из аккаунта» и «Удалить аккаунт». После выхода аккаунт и синхронизированные подписки остаются в базе. При подтверждении удаления сервер удаляет аккаунт, подписки и все сессии, а приложение очищает локальные данные аккаунта. Для удаления требуется подключение к серверу.

## Запуск Flutter

```powershell
cd mobile
flutter pub get
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000
```

`10.0.2.2` — адрес хоста для Android Emulator. Для iOS Simulator используйте `http://localhost:8000`. Для тестового аккаунта на физическом Android используйте USB-подключение по инструкции ниже.

## Каталог и ИИ

Каталог намеренно пустой до внесения проверенных цен. Для загрузки подготовьте JSON-массив с полями `service_name`, `plan_name`, `category`, `amount`, `currency` (`RUB`), `period` (`weekly`, `monthly`, `quarterly`, `yearly`), `source_url` (официальная HTTPS-страница), `checked_at` (`YYYY-MM-DD`). Затем выполните:

```powershell
cd backend
python -m app.import_catalog ..\catalog.json
```

Цена старше 30 дней помечается как требующая проверки. Рекомендации сравнивают эквивалентные месячные расходы в одной категории. Для формулировки ответа открытой моделью запустите совместимый локальный Ollama и задайте `OLLAMA_URL` и `OLLAMA_MODEL` в `.env`. Без этих переменных сервер возвращает проверяемый шаблонный ответ. Дообучение модели — последующий этап после сбора обезличенного и проверенного набора вопросов и ответов; персональные расходы в обучение не включаются по умолчанию.

## Ограничения текущего среза

- Восстановление пароля и добавление второго контакта к аккаунту пока не реализованы.
- Для банковского импорта поддерживаются текстовые PDF-выписки указанных форматов. Синхронизация напрямую с банковскими API пока недоступна.
- Уведомления планируются для ближайших циклов и обновляются при открытии приложения; для бессрочного серверного push-планировщика нужен отдельный сервис.
- Начальная схема БД создаётся при запуске. Перед публичным развёртыванием следует добавить миграции и резервное копирование PostgreSQL.


## Офлайн-режим

- Данные сохраняются на устройстве между перезапусками через SharedPreferences (локальное JSON-хранилище, не SQLite). Очистка данных приложения или удаление приложения удаляет локальные данные.
- После первого входа приложение автоматически открывается с данными аккаунта при недоступности сервера. Добавления, изменения, удаления и настройки напоминаний записываются в очередь. Синхронизация выполняется при открытии приложения, возврате в него, обновлении экрана и каждые 30 секунд, пока приложение запущено.
- Выход из аккаунта с неотправленными изменениями заблокирован, чтобы сохранить их. Если сессия истекла, пункт меню «Войти снова» позволяет возобновить синхронизацию в том же аккаунте.
- Данные, сохранённые в прежнем гостевом режиме, остаются в хранилище устройства. Текущий экран входа их не открывает и не импортирует в аккаунт.
- Для повторной отправки создания без дублей сервер принимает необязательный UUID подписки. Обновите сервер вместе с приложением. При изменении одной подписки на разных устройствах применяются последние доставленные изменения; объединения отдельных полей нет.
- Каталог и рекомендации сохраняются после загрузки. После локальных изменений старые рекомендации очищаются до синхронизации. Новые ответы помощника и свежие тарифы требуют сервера; нейросеть на телефон не встроена.
- Проверки: `flutter test`, `flutter analyze`, для сервера из папки `backend`: `.venv/Scripts/python.exe -m pytest`.


## Физический Android без Яндекса (USB)

Для USB-подключения соберите APK с адресом `http://127.0.0.1:8000` и тестовым входом. Из корня проекта выполните:

```powershell
cd mobile
flutter build apk --debug --dart-define=API_BASE_URL=http://127.0.0.1:8000
Copy-Item build/app/outputs/flutter-apk/app-debug.apk ../subscription_tree-android-usb.apk
cd ..
```

1. Включите на телефоне режим разработчика и «Отладку по USB», подключите USB-кабель и подтвердите разрешение отладки на телефоне.
2. Из папки проекта запустите `powershell -ExecutionPolicy Bypass -File .\run-android-usb.ps1`. Скрипт выбирает физический телефон, при необходимости запускает сервер, настраивает USB-подключение, устанавливает APK без очистки данных и открывает приложение.
3. Введите телефон или почту и пароль тестового аккаунта.
4. Для синхронизации оставьте компьютер и сервер включёнными, USB — подключённым. После переподключения USB запустите скрипт ещё раз. При потере соединения приложение открывает ранее сохранённые данные аккаунта.

Скрипт перенаправляет порт через `adb reverse`. Сервер слушает только `127.0.0.1:8000` на компьютере.
